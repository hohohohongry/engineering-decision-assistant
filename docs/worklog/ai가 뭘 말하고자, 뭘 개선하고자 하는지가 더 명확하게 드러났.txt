이 프로젝트가 해결하려는 문제 : 설계 대안을 판단할 때 자료가 많아질수록, 어떤 정보를 기준으로 봐야 하는지 찾고 → 후보별 근거를 다시 모으고 → 서로 다른 조건의 Trade-off를 비교하는 데 시간이 많이 들고, 판단 근거를 놓칠 수 있다.
이걸 개선하는 AI야.

정의: 여러 설계안과 분산된 개발자료를 판단 가능한 형태로 구조화해, 엔지니어가 대안의 Trade-off를 더 빠르고 일관되게 비교하도록 돕는 의사결정 지원 도구

기존에는: 사람이 직접 
자료 읽기
→ 중요한 판단항목 찾기
→ 후보별 정보 다시 찾아 정리
→ 단위/조건 비교
→ 장단점 정리
→ 조건 바뀌면 다시 판단

지금은:
자료 입력
→ 판단항목 추천
→ 후보별 근거 자동 구조화
→ 수치/정성정보 비교
→ 장단점·Trade-off 정리
→ 조건 변화 시 영향 재분석

크게 3가지 개선.
① 판단 준비시간 단축
자료를 읽고 후보별 표를 만드는 반복 작업을 줄임.

② 판단 누락 감소
사람이 처음 생각하지 못한 검출성, 조립성, 검증부담 같은 판단축이나 공통 근거를 AI가 추가로 제시.

③ 판단 근거의 일관성 향상
그때그때 감으로 판단하는 게 아니라 같은 기준과 근거 구조로 후보를 비교하고, 조건이 바뀌면 무엇이 달라지는지도 추적.

그니까.
정형 데이터(ex. 원가 10% 절감, 개발기간 3개월)는 파이썬 규칙으로 비교하고.
비정형 데이터(ex. 프리픽스처 공급으로 공장 조립 작업량을 줄일 수 있음, 완전 사전조립 모듈로 전환)라는 문장이면 LLM이 읽고, 판단 가능한 형태(ex. 항목:조립성/ 방향:긍정 / 근거:공장 조립 작업량 감소)로 바꾸는 역할.

그러면 이렇게 구조화된 결과를 파이썬이 항목별 우위 산출. 비교가 가능한 형태로 바꾼거니까.

그리고 비교표+원문증거를 바탕으로 LLM이 또, 의미 있는 설명을 만들어내는거지. 
ex) A안은 원가와 조립 부담 측면에서 유리하지만, 검사 기준과 공급 관리 측면에서는 추가 부담이 발생합니다. 따라서 제조 효율을 우선한다면 A안의 장점이 크지만, 품질 안정성을 중시할 경우 검사·운송 관리 방안에 대한 추가 검토가 필요합니다.

LLM 역할 요약: 규칙은 ‘무엇이 우위인지’를 일관되게 비교하고, LLM은 ‘왜 그런 결과가 나왔고 무엇을 추가로 검토해야 하는지’를 설명한다.

if, 판단 기준의 우선순위가 달라졌을땐?
파이썬이 새 조건에 따른 비교 결과 재계산. 그럼 결론이 달라지겠지.
그리고 LLM이 왜 결론이 달라졌는지 설명.
ex) 기존에는 원가와 조립성에서 우위인 A안이 유리했지만, 품질 안정성을 최우선으로 변경하면 검사 부담이 작은 B안의 중요도가 커집니다. 다만 B안은 제조 공수가 증가하므로 해당 비용 증가를 허용할 수 있는지 추가 검토가 필요합니다.


LLM 역할 쉽게 설명: 문장 의미 해석하기, 결과를 해석하고 설명하는 것, 조건 달라짐에 따라 결과가 왜 달라졌는지 설명하는 것.

자소서 쓸 문장 예시: 수치처럼 정형화된 정보는 규칙 기반으로 비교해 일관성을 확보하고, 문서마다 표현이 다른 정성적 근거는 LLM으로 해석·구조화했습니다. 이후 비교 결과와 원문 근거를 바탕으로 각 대안의 Trade-off와 추가 검토사항을 설명하도록 역할을 분리했습니다.
